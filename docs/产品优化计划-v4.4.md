# 产品优化计划（V4.4 · 以资深产品经理视角）

> 状态标记：✅ 本轮已上线　🟡 本轮只做了最小可用版　⬜ 排到下一轮
> 判断依据：用户从「输剧名」到「拿到收益」这条主链路上，哪一步最容易掉人。

## 一、结论先行：三个真正卡住用户的地方

| # | 问题 | 证据 | 处理 |
|---|---|---|---|
| 1 | 用户不知道「系统会替他把专业的事做掉」 | 九个专业库（情绪/运镜/光影/剪辑…）全在后端，用户看到的只是「生成中」 | ✅ 强制注入 + 前端显性化（剪辑打法卡） |
| 2 | 换设备等于换账号 | 只有微信登录，换号/换机=从零开始，作品全丢 | ✅ 手机号验证码 + 密码 + 绑定手机 |
| 3 | 赚了多少钱看不见 | 分发页只有单条任务的收益，没有汇总 | ✅ 收益看板（总额/结算/平台/月度/项目） |

## 二、逐项计划与完成情况

### 1. 创作链路：把「专业约束」变成产品能力 ✅
- 九个库统一收口到 `PromptLibrary`，每个环节声明必需库（剧本=情绪+节奏，分镜=运镜+光影+转场+特效，音视频=运镜+光影+特效+配乐+情绪，剪辑=配方+字幕+转场+配乐）。
- 硬闸门放在打上游之前：缺库直接拒绝，**不消耗用户点数**。
- 用户侧只暴露两个可调项（剪辑配方、字幕同步），其余按风格自动搭配——选择太多是负担。

### 2. 登录与账号 ✅
- 三条路：微信一键、手机号验证码、手机号密码。验证码未接服务商时**如实返回测试码**，不假装已发送。
- 账号安全页：绑定手机、设置/修改密码、退出登录。
- 密码用 scrypt + 随机盐；登录失败不区分「号不存在」与「密码错」，防探测。

### 3. 资产与额度 ✅
- ✅ 余额、充值、兑换、邀请返利已有；本轮补「收益看板」入口与总额。
- ✅ 额度预警（V4.5）：余额低于 `LOW_BALANCE_POINTS`（默认 300）时看板给红/黄条 + 去充值。
  刻意**不**做「按单价预测还能出几集」——单价随模型/时长/画质浮动，预测必然失真，用户会拿预测去对账。
- 🟡 账单还没有导出（对账要用），下一轮加 CSV 导出。

### 4. 分发与收益 ✅
- ✅ 平台选择、任务状态流转、合同、收益回填（带账期）、收益看板。
- ✅ 多平台批量回填（V4.5）：看板列「待回填清单」，抽屉里一次填完，整批校验归属、整批写入。
- ✅ 收益口径修正（V4.5）：金额与结算状态改以 `earnings` 账为准。
  之前读 `distributions` 上的兼容快照，导致「已结算」恒为 0、跨月拆不开；
  「按平台」也只认 `platform_code` 而 V3 主键是 `platform`，全部落到 unknown——两个都是真实 bug。
- 🟡 第三方平台无开放上传 API，只能「备齐材料 + 登记状态」，这点在界面上已明说，不假装代传。

### 5. UI / 动效 ✅ / 🟡
- ✅ 设计系统 v3：玻璃面板、统计卡、分段控件、纯 CSS 柱状图、底部弹层、骨架屏、标签体系。
- ✅ 两个新页面（登录、收益看板）全部用新组件；首页统计条加收益。
- 🟡 创作页与剧组页仍是 v2 视觉，下一轮统一到 v3（组件已备好，属于替换工作）。
- ⬜ 空态插画、成片预览的转场动效。

### 6. 可靠性（用户不会说但一定会骂） ✅
- ✅ 越权收敛：生产环境不允许用 `?userId=` 读别人数据。
- ✅ 推理模型探活误判修正（之前会把 DeepSeek-V4-Pro 判成「不可用」）。
- ⬜ 生成任务的断点续跑可视化（现在只有托管任务有进度）。

## 三、下一轮建议顺序（按投入产出比）

1. **成片预览 + 一键剪辑**：现在用户要拿到 mp4 依赖云端 ffmpeg，失败时只能看命令——这是转化率的最大漏斗。
2. ~~多平台批量回填~~ ✅ V4.5 已完成。
3. **账单导出 + 月度对账单**：有收入之后第一个被要的功能（数据源已备好，`earnings` 账可直接出 CSV）。
4. **创作页/剧组页视觉统一到 v3**：纯前端替换，风险低。
5. **模板市场**：把跑通的风格+配方组合做成「一键套用」，降低新用户起步成本。

## 四、明确不做的事（本轮）

- 不做短信服务商接入：没有账号资质，先用 dev 模式把链路跑通，接口留好。
- 不做平台代传：没有开放 API，硬做就是骗用户。
- 不做多人协作：单用户单作品集的结构撑不住，得先改数据模型。
