# 素材改编：用自己的故事直接开拍

> 适用于 V4.6 及以后。这条路是给「手上已经有成熟创意、不想让 AI 从头编」的创作者准备的。

## 为什么有这条路

之前只有一种创作方式：给一个题材方向，系统生成创意剧本。这适合还没故事的人，
但对已经有小说、剧本、或者脑子里已经想清楚整条线的创作者来说，是多余的工序——
他们真正需要的是「把我现成的东西快速变成能发的竖屏短剧」。

V4.6 补上了这条路，两条路共用同一套生产链，区别只在**剧本从哪来**。

## 完整流程

```
新建项目
  ├─ 选「改编我的素材」      ← 这条是新加的
  ├─ 贴入正文（≥200 字）      ← 小说/剧本正文，或从微信聊天选 TXT
  ├─ 选「改到什么程度」        ← 忠于原著 / 按短剧重排
  ↓
进入剧组（自动落在「素材」tab，正文已存好）
  ↓
选风格（古风 / 仙侠 / 现代修真 / 玄幻 … 共 32 种）
  ↓
点「按我的素材生成剧本」→ 大纲 + 剧集划分 + 分镜
  ↓
生成角色 / 道具 / 场景资产（造型锁定，后续每集沿用）
  ↓
出分镜图 → 转视频（音视频生成）
  ↓
剪辑成片（字幕同步 + 混音 + 编码）
  ↓
备齐材料 → 上传到分发平台 → 回收益看板填钱
```

项目页顶部有一条**改编流水线**（仅素材改编路线显示），按真实产物点亮：
素材 → 生成剧本 → 剧集划分 → 角色场景 → 分镜图 → 剪辑成片 → 分发上架。
点任意节点直达对应 tab，并且会告诉你「下一步做什么」。

## 两个关键设计

**1. 选了改编却没素材，系统不会偷偷编一个故事**

`POST /api/projects/:id/plan` 里有硬校验：`spec.origin === 'material'` 且素材正文为空时，
直接返回 `MATERIAL_REQUIRED`，提示「先上传小说正文或剧本文本」。
道理很简单——那不是改编，是偷换。用户以为自己拍的是他的故事，实际拿到的是 AI 编的另一个。

**2. 改编强度必须真的改变给模型的指令**

| 模式 | 给模型的指令 | 适用 |
|---|---|---|
| 忠于原著 `faithful` | 保留主线、人物关系与关键台词，只做竖屏拆分，**不得改动结局** | 已有完整作品，只想影视化 |
| 按短剧重排 `remix` | 保留设定与人物，允许重排节奏、合并次要人物、加强钩子，但**世界观与主角动机不得改变** | 有故事骨架，要适配竖屏节奏 |

这段文案抽在 `StoryEngine.adaptInstruction()` 里，由 `tests/adapt_route.test.js` 锁住，
避免以后有人改提示词时把「不得改动结局」删掉。

## 格式支持

| 格式 | 支持情况 |
|---|---|
| 纯文本粘贴 | ✅ 前端直接贴，最多 20000 字 |
| TXT / MD | ✅ 从微信聊天里选，前端读入（≤2MB） |
| DOCX | ⚠️ 前端解不了压缩包，需建组后在「素材」页选「TXT / DOCX」，服务端自动取正文 |
| 参考图 / 参考视频 | ✅ 建组后素材页上传，作为造型与画面参考 |

## 和其他功能的关系

- **九大提示词库**照旧强制注入：改编路线一样要带齐情绪/运镜/光影等库，否则拒绝生成。
- **计费**不变：按实际算力 ×2 扣点，创建项目和上传素材本身不扣点。
- **续集**：改编项目同样可以「拍下一季」，继承设定但不继承画面。
- **旧项目**：没有 `origin` 字段的历史项目一律按「AI 出创意」处理，不受影响。
