# 微信虚拟支付接入指南（微短剧 / 点数包）

> 这份文档回答一个问题：**用户在 App 里买点数，钱怎么收上来。**
> 代码侧已经全部就位（`server/src/pay/VirtualPay.js` + `server/src/wechat/WechatClient.js`），
> 你实际要做的是「后台开通 + 填环境变量 + 回调登记 + 沙箱验一遍」这四步。

---

## 0. 先搞清楚为什么必须用「虚拟支付」

| 端 | 卖点数包（虚拟商品）能用的通道 |
|---|---|
| Android | 微信支付（JSAPI）或虚拟支付都行 |
| **iOS** | **只能走微信虚拟支付**，走微信支付/第三方支付会被判「规避苹果 IAP」直接拒审 |

所以本项目从一开始就走微信官方的**虚拟支付**：一套代码两端通吃，不用按平台分叉。

---

## 1. 后台开通（一次性，1–3 个工作日）

1. 小程序后台 → **功能 → 虚拟支付** → 申请开通。
   - 需要：企业主体、已认证、类目属于「文娱-微短剧」或「工具-内容创作」之类允许虚拟支付的类目。
   - 审核通过后，**功能 → 虚拟支付 → 基础配置** 里会出现 `OfferID` 和 `AppKey`。
2. 同一页面的 **「支付回调 / 发货回调」** 里填：

   ```
   https://你的域名/api/pay/virtual/notify
   ```

   > 必须是 https、必须外网可达、不能带参数。云托管默认域名可以直接用。
3. **「支付形态」** 选 `short_series_goods`（微短剧道具直购）。
   本项目卖的是点数包，不是代币，所以不走 `short_series_coin`。

---

## 2. 填环境变量（云托管 → 服务设置 → 环境变量）

| 变量 | 必填 | 说明 |
|---|---|---|
| `WX_APPID` | ✅ | 小程序 AppID（登录与签名都要） |
| `WX_SECRET` | ✅ | AppSecret。**只放服务端**，不要写进小程序代码 |
| `WX_PAY_OFFER_ID` | ✅ | 上一步拿到的 OfferID，形如 `1450000000` |
| `WX_PAY_APP_KEY` | ✅ | 虚拟支付 AppKey（签名密钥） |
| `WX_PAY_ENV` | ✅ | `1` = 沙箱，`0` = 正式。**联调必须 1** |
| `WX_PAY_MODE` | 建议 | 默认 `short_series_goods` |
| `WX_PAY_NOTIFY_URL` | 建议 | 回调地址，仅用于自检展示 |

填完重启服务，然后打开体检接口：

```
GET /api/pay/virtual/status
```

它会把「还差哪一步」直接列出来（`missing: ["app_key"]` 这种），不用猜。

---

## 3. 一次支付到底发生了什么

```
小程序                     服务端                        微信
  │  选档位 ¥6 / 60 点
  │── POST /api/pay/virtual/order ──▶
  │                                 建单 pending
  │                                 signData = {offerId, buyQuantity:60, env, currencyType, platform, zoneId}
  │                                 paySig   = HMAC-SHA256(app_key, "requestVirtualPayment&" + signData)
  │                                 signature= HMAC-SHA256(session_key, signData)
  │◀── { requestVirtualPayment } ───
  │
  │── wx.requestVirtualPayment({...}) ─────────────────────▶ 收银台
  │◀────────────────────────────── success（用户付完了，但点数还没到）
  │
  │                                  ◀──── POST /api/pay/virtual/notify（发货回调，验签）
  │                                 订单 → paid，点数入账（幂等键 = 微信订单号）
  │── POST /api/pay/virtual/query（轮询，最多 ~12s）──▶
  │◀── { paid: true, points: 60 }
```

三个容易踩的点，代码里已经处理：

1. **`success` ≠ 到账。** 到账只认发货回调；前端改成轮询 `query`，不再"等 1.5 秒就当到了"。
2. **签名必须用 `session_key`。** 它在 `wx.login` 的 `jscode2session` 里返回，登录时已落库到用户记录
   （`wx_session_key`，`publicUser` 是白名单，不会外泄）。拿不到 session_key 时签名会标注 mock，
   并在下单响应里给出 `hint`，不会假装成功。
3. **`signData` 必须是紧凑 JSON**，字段顺序固定。多加一个空格整笔支付就签名失败。

---

## 4. 沙箱联调怎么走

1. `WX_PAY_ENV=1`，重启服务。
2. 小程序「我的 → 充值」选一个档位 → 支付。
3. 沙箱下微信不会真扣钱，回调也照常发。
4. 验证三件事：
   - `GET /api/pay/virtual/orders` 里那笔单变成 `paid`；
   - 用户余额增加了对应点数；
   - 同一条回调重复投递不会重复加点（幂等键 `wxpay:{微信订单号}`）。

**没有商户号时（本地开发）**：接口返回 `mode: 'mock'`，前端走 `POST /api/pay/virtual/mock-success`，
点数立即到账但**不产生真实扣款**，页面会明确写「内测支付通道」。
一旦配了 `WX_PAY_OFFER_ID` + `WX_PAY_APP_KEY`，mock 发货会被服务端**强制禁用**（否则等于送钱）。

---

## 5. 上线前的四个必须

- [ ] `WX_PAY_ENV=0`（忘了改会一直走沙箱，用户付的是假钱）
- [ ] 回调地址已在虚拟支付后台登记，且能被微信访问到（用 `curl` 打一次看是否 200/JSON）
- [ ] 价格与点数包在**虚拟支付后台**也建了对应商品（金额必须与本地档位一致，否则微信侧拒单）
- [ ] iOS 真机完整走一遍：下单 → 收银台 → 到账 → 余额变化

---

## 6. 退款

虚拟支付退款走微信后台的「退款」入口，或调用虚拟支付退款接口。
本项目只做「点数入账」，不自动处理退款——退款后需要人工扣点：

```
POST /api/admin/ledger/adjust   { userId, points: -60, reason: "虚拟支付退款 order_xxx" }
```

（管理后台「用户 → 调账」是同一个入口，会写审计日志。）
