## 一、模板选择：10 个选项里选 Express.js

控制台当前给的 10 个模板，逐一判断：

| 模板 | 结论 | 说明 |
|---|---|---|
| **Express.js** | ✅ **首选** | Node 运行时，与本项目一致；模板骨架最薄（`index.js` + `package.json` + `Dockerfile`），删掉换成仓库代码最省事 |
| Koa | ✅ 次选 | 同为 Node，也能用；模板多带 `koa-router` 等中间件，清理略麻烦一点 |
| Golang | ❌ | 语言不匹配 |
| Spring Boot | ❌ | 语言不匹配 |
| .NET Core | ❌ | 语言不匹配 |
| Django | ❌ | 语言不匹配 |
| Flask | ❌ | 语言不匹配 |
| ThinkPHP (Nginx) | ❌ | 语言不匹配 |
| ThinkPHP (Apache) | ❌ | 语言不匹配 |
| Laravel | ❌ | 语言不匹配 |

**关键认知**：这 10 个都是「示例工程」，不是「运行时」。选 Express 只会给你一份 hello world，不会让本项目跑起来。
本项目的服务端是**零第三方运行时依赖**，入口是 `server/src/index.js`，所以模板代码只当占位，选完必须做三件事：

1. 删掉模板自带的 `index.js`、`package.json`、`Dockerfile`，以及它的 `container.config.json`。
2. 把本仓库代码放进同一分支（根目录已有 `Dockerfile`、`container.config.json`、`.dockerignore`）。
3. 重新建版本，确认构建日志里是 `node:22-alpine`、启动命令 `node src/index.js`。

> ⚠️ 模板自带的 Node 版本一般是 16/18，本项目 `engines: node >= 22`，**必须**用仓库里的 Dockerfile（`FROM node:22-alpine`），不要沿用模板那份。
> 如果控制台另有「自定义 / 空白 / 不使用模板」入口，直接选它，可以省掉上面三步。

本仓库根目录已放好 `container.config.json`，云托管建版本时会读它，端口、实例数、CPU/内存、环境变量都不用在页面上逐个点：

```json
{ "containerPort": 80, "dockerfilePath": "Dockerfile", "minNum": 1, "maxNum": 1,
  "cpu": 0.5, "mem": 1, "envParams": { "NODE_ENV": "production", "HOST": "0.0.0.0",
  "PORT": "80", "DATA_DIR": "/data" } }
```

## 二、必须照抄的服务参数

| 项 | 值 | 说明 |
|---|---|---|
| 容器端口 | **80** | 云托管网关默认转发到 80。镜像里 `ENV PORT=8787` 会被运行时环境变量 `PORT=80` 覆盖，`HEALTHCHECK` 也已改成读 `$PORT` |
| CPU / 内存 | 0.5 核 / **1 GB** | 素材上传会把整个请求体读进内存（视频上限 24 MB），0.5 GB 容易 OOM |
| 最小实例数 | 1 | 设 0 会冷启动，小程序首屏白屏 3–10 秒 |
| 最大实例数 | **1（不要改）** | 见 §四，这是硬约束 |
| 健康检查 | HTTP `GET /health` | 服务端已内置，返回版本与数据目录 |
| 公网访问 | **开启** | 小程序 `wx.request` 要打公网域名 |
| 日志 | stdout | 服务端只往 stdout 打，不用配日志路径 |

## 三、环境变量（控制台配，绝不进镜像）

必填：

| 变量 | 值 | 备注 |
|---|---|---|
| `PORT` | `80` | 与容器端口一致 |
| `HOST` | `0.0.0.0` | 不填默认就是它，显式写上更保险 |
| `DATA_DIR` | `/data` | 必须与文件存储挂载点一致 |
| `NODE_ENV` | `production` | |
| `WX_APPID` | `wxe3380ec60a48931d` | 当前小程序 |
| `WX_SECRET` | 小程序密钥 | 敏感，只在控制台 |
| `SESSION_SECRET` | **固定随机串**（≥32 位） | ⚠️ 不填则进程内随机生成，**每次发布所有人登录态失效** |
| `ADMIN_TOKEN` | 自定强口令 | 不填则管理端接口一律 403 |
| `RELAY_API_KEY` | 中转站 Key | 不填会自动降级到 mock（不会真出图）。**也可以不配这里**，改在管理台「算力网关」填（存数据盘、立即生效、轮换不用发版） |
| `RELAY_GATEWAY` | `https://api.lingkeai.ai/v1` | |
| `RELAY_MOCK` | `false` | 生产必须显式 false |

密钥怎么给最省事（V4.3.1 起推荐）：

1. 打开 `https://<域名>/admin.html`，输入 `ADMIN_TOKEN` 进后台；
2. 找到「算力网关」卡片，粘贴密钥（`sk-...`）→ 保存并生效；
3. 点「保存后探活」——全部可用会提示「探活通过」，有下架模型会点名。
4. 命令行复核：`node scripts/live_relay_check.js`（走完整编译+鉴权+计费链，打一句真实编剧指令）。

密钥存在数据盘 `app_settings`（`relay_runtime`），**不写进代码仓库**；`/health` 的 `relay.mode` 会从 `mock` 变 `live`。

按需：`WX_PAY_OFFER_ID` / `WX_PAY_APP_KEY` / `WX_PAY_MCHID` / `WX_PAY_NOTIFY_URL` / `WX_PAY_ENV`（虚拟支付）、`PUBLIC_WORKSPACE_URL`（合规包里的工作台地址）、`POOL_*`（算力水位告警）。

> 端口改动只需改环境变量，不用重打镜像——`config.server.port` 读的就是 `process.env.PORT`。

## 四、数据持久化：不挂文件存储 = 每次发布数据全丢

当前持久化是 **JSON 文件**（`server/src/store/db.js`：进程内缓存 + 50ms 防抖整文件重写），落在 `DATA_DIR`，素材文件落在 `DATA_DIR/uploads`。容器磁盘是临时的，**发布/重启即清空**。

必须做两件事：

1. **控制台 → 服务配置 → 文件存储（CFS）**，新建并挂载到 **`/data`**。首次挂载后进去确认目录可写。
2. **最大实例数锁死 1**。原因：`db.js` 是「读进内存 → 改内存 → 定时整文件覆盖写」，两个实例各写各的，后写的会把先写的数据整段覆盖（不是丢一条，是丢一批）。挂 CFS 也救不了，因为 CFS 不带文件锁。

> 要横向扩容，唯一正路是把 `db.js` 换成云托管自带的 MySQL（接口形状已经对齐，业务层可零改动替换）。在换之前，**1 实例**是硬约束。

备份：CFS 里的 `*.json` + `uploads/` 直接打包即可；本地 `server/data/` 结构完全一致，可整目录迁上去。

## 五、小程序侧要改一处 + 配三类域名

1. `miniprogram/config.js` 把 `trial` / `release` 换成云托管公网域名：

```js
trial:   'https://<环境ID>-<服务名>.sh.run.tcloudbase.com',
release: 'https://<环境ID>-<服务名>.sh.run.tcloudbase.com',
```

2. 微信公众平台 → 开发管理 → 服务器域名，三类都要加（只加 request 会踩坑）：

| 类型 | 为什么要 |
|---|---|
| request 合法域名 | 所有 `/api/*` 调用 |
| uploadFile 合法域名 | 素材上传走 `wx.uploadFile`（multipart） |
| downloadFile 合法域名 | `<image>` / `<video>` 加载 `/media/*` 走的是 downloadFile 校验 |

> ⚠️ **上面这张表是错的，别照做。**
>
> 微信官方明确规定：**云托管默认公网域名不允许配置到小程序后台的服务器域名**，
> 「默认公网域名性能有限制，仅能支持接口测试使用，请勿用于正式生产环境。小程序后台也无法配置使用默认公网域名。」
>
> 实测在 mp 后台填 `https://xxx.sh.run.tcloudbase.com` 会直接被拒。
>
> **正确的做法是 `wx.cloud.callContainer`**（小程序内网通道）：
> 走微信内部链路，不带公网域名，**完全不需要配服务器域名，也不需要备案**。
> 本项目已在 `utils/api.js` 里做成默认主通道，详见 `docs/网络异常排查.md`。
>
> 只有两种情况才需要域名：① 你要给 H5/其他小程序访问；② 你要在浏览器里直接打开接口调试。

## 六、四个已知风险（按严重度，部署前先看）

1. **视频生成会超时（最可能翻车）**。`RelayAdapter.#pollTask` 最长轮询 10 分钟并同步等结果，小程序 `generateShot` 超时设的是 180 秒。云托管网关 + 小程序双层超时下，真实视频任务大概率 504 / `request:fail timeout`。
   正解：把生成改成「提交任务 → 返回 taskId → 前端轮询 `GET /api/projects/:id/shots/:no/generations`」。
2. **24 MB 视频上传可能被网关拦**。上传是整包 multipart 进内存，需实测云托管请求体上限；若被拦，改分片或前端直传 COS 再回填 URL。
3. **单实例 = 发布期间短暂不可用**。用灰度发布（先 10% 流量）或挑低峰发布。
4. **计费**。`minNum=1` 是 7×24 常驻计费（有月度免费额度可抵），`minNum=0` 省钱但有冷启动。先按 1 跑一周看账单再决定。

## 七、部署步骤

> **重要前提（2026-11-05 实测）**：微信云托管（cloud.weixin.qq.com 侧的 `WeixinCloud` 环境）**不属于**腾讯云账号体系，腾讯云 SecretId/SecretKey 走 `tcb` CLI 看不到它（`tcb env:list` 为空是正常现象，不是密钥错了）。
> 可用的部署通道只有两条：**GitHub 流水线（推荐，push 即自动发版）** 或 **控制台上传代码包**。

### 通道 A：GitHub 流水线（推荐，一次配置终身自动）

1. GitHub 建好仓库并推送本仓库代码（`Dockerfile`、`container.config.json` 都在根目录）。
2. 打开 https://cloud.weixin.qq.com/cloudrun → 选环境 `WeixinCloud` → 服务 `wxcloudrun-express`。
3. 「新建流水线」→ 授权 GitHub → 选仓库 `Magellan12440/wangjudaka`、分支 `main`。
4. 构建方式选 **Dockerfile**，路径 `Dockerfile`，构建目录留空（根目录）。
5. 触发规则勾选「push 到 main 自动触发」→ 保存并手动跑一次。
6. 首次发布前按 §三 填环境变量（至少 `SESSION_SECRET`、`ADMIN_TOKEN`），并**挂文件存储到 `/data`**（§四）。
7. 以后每次 `git push` 都会自动构建发版——这就是「迭代后自动更新」。

### 通道 B：控制台上传代码包（立刻可用，不等 GitHub）

1. 用仓库根目录的发布包 `dist/wangjudaka-cloudrun-4.3.0.zip`（由 `git archive` 生成，不含密钥/依赖/历史，含全部 15 个种子库）。
2. https://cloud.weixin.qq.com/cloudrun → 环境 `WeixinCloud` → 服务 `wxcloudrun-express` →「新建版本」→「上传代码包」→ 选这个 zip。
3. Dockerfile 路径 `Dockerfile`，端口 80（`container.config.json` 会自动带全量参数）。
4. 同样先配 §三 环境变量 + §四 文件存储，再点发布。
5. 发布完测 `GET https://express-r0ph-341726-13-1525512932.sh.run.tcloudbase.com/health`，应返回 `{"ok":true,...,"version":"4.3.1"}`。

> **怎么确认线上跑的是不是新镜像**：看 `version` 字段。`4.3.1` = 本轮迭代版本（含越权收敛）；`4.3.0`/`4.2.x` = 旧镜像。
> 若返回 `Cannot GET /health`，说明容器里根本不是本项目（模板镜像），别怀疑代码，去查服务与域名是否对得上。

### 域名与服务的对应关系（最常见的一次踩坑）

`sh.run.tcloudbase.com` 的域名形如 `<服务名>-<随机串>-<环境ID>.<region>.sh.run.tcloudbase.com`。
因此 `express-r0ph-341726-...` 这个域名**很可能属于名为 `express-r0ph` 的服务**（用 Express 模板建环境时自动创建的那个），而不是 `wxcloudrun-express`。

现象：在 A 服务发布成功，但打开 B 服务的域名，永远看到模板页。

处理：进「服务列表」，逐条看**默认域名**，找到域名为 `express-r0ph-341726-...` 的那个服务，**在新版本选服务时就选它**；或者把小程序 `config.js` 的域名换成你实际发布成功那个服务的域名。

### 实例起不来的两类报错

| 日志 | 原因 | 已做的修复 |
|---|---|---|
| `AppError: 种子文件缺失: xxx.json` | `server/.gitignore` 的 `data/` 规则误伤了 `server/src/seeds/data/`，种子从未进仓库 | 已改锚定 `/data/`，种子全部入库；`deploy:check` 加了防复发检查 |
| `Back-off restarting failed container`（无业务报错） | 容器听的端口与平台探活端口不一致（旧镜像默认 8787） | Dockerfile 默认 `PORT=80`；生产环境**同时监听 80 / 3000 / 8080 / 8787**，任一被探到即可通过 |
| 任意启动异常 | 旧代码在种子缺失时直接 throw，容器进 CrashLoop，日志只能看到 Back-off | 4.2.1 起**降级启动**：缺种子也返回 200，`/health` 里给出 `seeds_ok:false` + `seeds_missing:[...]` + `seeds_problems:[...]` |


### 通用验证清单（发版后必做）

6. 小程序 `config.js` 已指向云托管域名（v4.2.0 已改好）→ 公众平台后台配齐 request / uploadFile / downloadFile 三类合法域名。
7. 真机走一遍「一句话成剧 → 逐镜出图 → 交付页渲染 → 分发」全链路。

> 镜像不需要 `npm install`（零运行时依赖），构建通常 30–60 秒；`.dockerignore` 已把 `miniprogram/`、`docs/`、`dist/`、`**/.env*` 挡在构建上下文外。

## 十一、云存储（V4.8）：素材与产物到底存在哪

### 为什么必须上云存储

云托管容器的文件系统是**临时**的：缩容到 0、重新部署、更换实例，`data/uploads` 里的东西全部消失。
更要命的是 `/media/*` 走的是 downloadFile 合法域名，而云托管默认域名**配不进**小程序白名单
（官方硬规则，见《网络异常排查》第五节）。所以：

- 素材、生成产物 → 微信云开发存储桶，返回 `cloud://` fileID；
- 小程序渲染前用 `wx.cloud.getTempFileURL` 换临时链接（走云开发 SDK，不受域名白名单限制）；
- 上传用 `wx.cloud.uploadFile` 直传（同样不受白名单限制，也没有 callContainer 100KiB 请求体上限）。

### 服务端怎么把文件写进桶

不用 `wx` 官方的 `/tcb/uploadfile`（那是给小程序 `wx.uploadFile` 用的，服务端直传恒 403）。
实际链路：

```
access_token  →  POST /tcb/getqcloudtoken  →  临时腾讯云密钥（2h）
              →  COS q-sign-algorithm=sha1 签名
              →  PUT https://<bucket>.cos.<region>.myqcloud.com/<key>
```

实现见 `server/src/storage/ObjectStore.js`，自检：

```bash
npm run storage:check          # 真上传 → HEAD 核大小 → 换临时链接 → 回读 → 删除
```

`storage:check` 不碰业务数据（对象键固定 `_selftest/`，跑完即删）。

### 必须配的环境变量（云托管控制台 → 服务设置 → 环境变量）

| 变量 | 必填 | 说明 |
|---|---|---|
| `COS_BUCKET` | 是 | `7072-prod-<env>-<appid>` 这种形态 |
| `COS_REGION` | 是 | `ap-shanghai` |
| `TCB_ENV` | 否 | 留空会从 `COS_BUCKET` 反推，一般不用填 |
| `STORAGE_PROVIDER` | 否 | 默认 `auto`（能云就云）；`cloud` = 强制云、失败即报错；`local` = 强制本地 |
| `WX_APPID` / `WX_SECRET` | **是** | 换 access_token 用；**缺了云存储必然降级本地** |
| `SESSION_SECRET` | 建议 | 不配则每次重启随机生成，所有登录态失效 |
| `ADMIN_PHONE` / `ADMIN_PASSWORD` | 建议 | 内置管理员账号 |
| `RELAY_API_KEY` | 是 | 算力网关密钥 |

> **降级不静默**：`/health` 的 `storage` 段会如实给出 `mode`（`cloud`/`local`）、
> `configured`、`last_error`。看到 `mode:"local"` 就是没配好，别猜。

### 发版脚本

`scripts/tcb_deploy.py` 走云托管 OpenAPI（`getqcloudtoken` → TC3 签名）：

```bash
python scripts/tcb_deploy.py info            # 看线上版本、流量比、构建方式
python scripts/tcb_deploy.py deploy          # 从仓库 main 构建新版本
python scripts/tcb_deploy.py buildlog <id>   # 构建日志
```

> 版本状态含义：`creating` 构建中 / `normal` 可用 / `build_failed` 构建机失败 /
> `deploy_failed` **镜像构建成功但实例没起来**——这两种失败原因完全不同，别混为一谈。
> 另外 `getqcloudtoken` 有**每日调用配额**，撞到 `errcode 45009` 只能等次日；
> 脚本会把密钥缓存到 `scripts/.tcb_cred.json`（已 gitignore）减少调用。

> push 到 GitHub `main` 会**自动触发**构建与部署，不一定需要手动 deploy。
