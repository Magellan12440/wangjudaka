# 小程序「网络异常」排查手册

小程序里所有的 `wx.request` 失败，在旧版本里都只显示一句「网络异常，请稍后重试」。
这句话掩盖了至少四种完全不同的原因，是排查成本最高的一句话。本文记录已知原因与定位方法。

## 一、先分清「谁的错」

在「我的 → 关于 → 网络自检」点一下（v1.0.261113 起有），会直接告诉你：

- **连的是哪个域名**
- **耗时多少毫秒**
- **成功时**：后端版本号 + 算力网关模式
- **失败时**：具体原因（域名未加白名单 / 请求超时 / 证书校验失败 / 网络不可达）

自检不依赖登录态，冷启动就能用，失败了也不会弹窗打断。

## 二、已踩过的坑（按出现频率）

### 1. 开发版连的是局域网 IP（本次根因）

`miniprogram/config.js` 里 `develop` 曾经写的是 `http://192.168.1.123:8787`。
手机上的 `192.168.x.x` 是手机自己所在网段，不是你的电脑，必然连不上。
换网、出门、后端没起，表现完全一样：一句「网络异常」。

**已修**：`develop` / `trial` / `release` 三个环境现在都直连云托管 https 域名。
本地联调要连本机后端时，不改代码，在开发者工具控制台执行：

```js
wx.setStorageSync('dev_host', 'http://192.168.1.123:8787')  // 只对开发版生效
wx.removeStorageSync('dev_host')                             // 换回云端
```

### 2. 域名没进 request 合法域名

除了「调试模式」，微信真机一律校验白名单。报错原文是
`request:fail url not in domain list`。

**必须手动配**（无开放接口，第三方代小程序接口需要授权，个人主体用不了）：

> https://mp.weixin.qq.com → 开发管理 → 开发设置 → 服务器域名 → request 合法域名
> 添加：`https://express-r0ph-341726-13-1525512932.sh.run.tcloudbase.com`

配置每月只能改 5 次，改完要**重新编译**（真机要重进小程序）才生效。

### 3. `getApp()` 还没就绪，base 退化成 127.0.0.1

`utils/api.js` 原来在拿不到 `globalData.baseUrl` 时回退到 `http://127.0.0.1:8787`。
如果是页面先于 App 实例化、或者在 Node 里跑自测，就会退到这个地址。

**已修**：回退目标改成 `config.baseUrl`（云端地址），127.0.0.1 不再出现在任何默认路径上。

### 4. 后端实例缩容到 0，冷启动超时

云托管 `MinNum=0`，一段时间没请求实例会被回收，下一次请求要等容器拉起。
实测冷启动 30~60 秒，超过小程序默认 60 秒等待就表现为超时。

**已做**：`app.json` 显式声明 `networkTimeout.request = 30000`；
启动时先打 `/health` 预热，用户点进去时实例已经在拉起了。
如果频繁遇到，把云托管的最小实例数改成 1。

### 5. 证书链

用完整根证书库校验过：TLS 1.3，DigiCert 签发，`*.tcloudbase.com`，**链完整、校验通过**。
不是这一类问题。若以后换自定义域名出现 `SSL_ERROR`，优先查中间证书是否漏装。

## 三、服务端自证清白的方法

前端报网络异常时，先在电脑上直接打接口，能区分「后端挂了」还是「前端连错了」：

```bash
B=https://express-r0ph-341726-13-1525512932.sh.run.tcloudbase.com
curl -s $B/health
curl -s -X POST $B/api/auth/login -H 'Content-Type: application/json' \
  -d '{"code":"probe_001","nickname":"探针"}'
```

两条都正常返回 → 问题一定在小程序端（地址 / 白名单 / 缓存）。
`/health` 里 `version` 还能确认线上跑的是哪个版本。

## 四、改完前端要做什么

1. `npm run mini:check`（15 组静态检查）与 `npm run mini:sim`（127 条交互仿真）必须全绿；
2. `npm run mini:upload -- --version 1.0.xxxxxx`；
3. mp 后台「版本管理 → 开发版本」→ 选为体验版 或 直接提交审核；
4. **白名单没配的话，前 3 步做完还是网络异常**——这是唯一一步代码救不了的。

## 五、正解：走内网通道，不要域名（v1.0.261115 起为默认主通道）

**先记住这条硬规则**：微信云托管默认公网域名 `xxx.sh.run.tcloudbase.com`
**不允许**配进小程序后台的服务器域名，填了会被拒：

> 官方原文：「默认公网域名性能有限制，仅能支持接口测试使用，请勿用于正式生产环境。
> 小程序后台也无法配置使用默认公网域名。」

所以「去后台加 request 合法域名」这条路对云托管是死的。正解是 `wx.cloud.callContainer`：

> 「小程序/公众号可使用 CallContainer，**无需域名**，因此不需要在 mp 管理后台配置服务器域名，
> 从而一开始就无需申请域名，也无需备案。」

### 现在的通道策略

```
本地联调（baseUrl 是 http://） → 先公网 wx.request，失败再内网
其它（云端 https）              → 先内网 callContainer，失败再公网
```

反过来（先公网）会让每个请求都先撞一次「域名未加白名单」，白费一次往返，所以默认顺序按地址判断。

### callContainer 的四条硬限制

| 限制 | 值 | 影响 |
|---|---|---|
| timeout 上限 | **15 秒**（传更大无效） | 代码里统一收敛到 14s；AI 生成长任务必须异步化 |
| 请求体 | ≤ 100 KiB | 大文本 / base64 传文件走不通 |
| 返回体 | ≤ 1000 KiB | 大 JSON 要分页 |
| 基础库 | **≥ 2.23.0** | 还要在 mp 后台「设置 → 功能设置 → 基础库最低版本」设成 2.23.0+ |

### 内网通道也救不了的地方（待改造）

| 场景 | 现状 | 解法 |
|---|---|---|
| 素材上传 `wx.uploadFile` | 只能走公网 → 必失败 | 改 `wx.cloud.uploadFile` 直传云存储，后端拿 fileID 取 |
| `<image>`/`<video>` 加载 `/media/*` | 需 downloadFile 白名单 → 必失败 | 媒体迁云存储，用 `cloud://` 直出 |
| 素材落盘位置 | 存在**容器本地磁盘** | 云托管容器重启即还原，必须迁 COS |

> 换句话说：接口全通之后，**图片/视频显示和素材上传**是下一关，
> 而它们和域名无关，和「文件存在哪」有关。

### 怎么确认走的是哪条

「我的 → 关于 → 网络自检」会分别列出公网与内网的结果，并显示当前用的是哪条通道。
